# 입찰 업무 관리 확장 — 2026-11-03

## 적용 범위

기존 `/gcal` 화면에 진행 중·오늘 마감·협정 미완료·가격제시 미완료·투찰 미완료 바로보기를 추가한다.
진행 중은 취소되지 않았고 투찰마감 전이거나 마감 시각을 확인하지 못한 공고다.
세리공영·진유의 참가/협정완료/투찰완료와 가격제시 업체별 완료 상태를 별도로 저장한다.
기존 공고 상태·담당자·메모·적색 제출완료 동기화는 보존한다.
기존 제출완료 표시는 개별 회사의 완료를 자동 확정하지 않으며, 목록에서 회사별 확인이 필요함을 표시한다.

기호 해석: ㅇ=세리공영, ?=진유, ㅁ=지역공동도급 대상, ◆=전기공사업,
&=관리자 yh 표시, #=가격제시 대상, @=통신공사업, 소수점 세 자리 비율=입찰 하한율.
ㅁ은 협정완료로 해석하지 않는다. &는 담당자를 자동 변경하지 않는다.
# 업체명은 원문을 확인한 후 직접 입력한다.

신규 업무는 `gcal_bid_workflow` 테이블에 저장되어 캘린더 갱신이 덮어쓰지 않는다.
동시 편집은 저장 전 JSON 비교로 충돌을 감지한다. 충돌 시 목록을 조회하고 편집창을 다시 열어야 한다.
업무 저장 후 기존 상태/메모 저장이 실패하면 부분 저장 사실을 알리고 재시도할 수 있다.

목록은 API의 전체 건수를 확인해 모든 페이지를 읽는다. 시간은 한국시간(KST)으로 해석한다.
취소·마감 건은 미완료 업무에 집계하지 않는다. 날짜만 있는 값은 마감 시각 미확인으로 취급한다.
화면의 1분 갱신은 남은 시간과 집계만 갱신하며 캘린더를 자동 동기화하지 않는다.

## 검증

Node.js 24 이상에서 `npm ci`, `npm test`.
테스트는 회사별 완료, 취소/마감 제외, 협정 마감, 업체별 가격제시, KST 해석,
기존 메모 보존, API 저장, 동시 편집 충돌, 페이지 구분, 화면 HTML을 검증한다.
로컬 D1에서 기존 마이그레이션 및 0006 신규 테이블 생성 통과.
브라우저 시각 검증은 Wrangler의 uv_interface_addresses 환경 오류로 수행하지 못했다.

## 배포 순서와 현재 제한

1. 운영 코드 버전 및 Cloudflare 계정을 확인하고 운영 D1 백업을 확보한다.
2. 운영 설정의 실제 D1 바인딩을 사용한다. 저장소 wrangler.jsonc의
   `database_id: local-dev-placeholder`는 로컬용이며 운영 DB 식별자가 아니다.
3. 운영에 기존 테이블이 이미 수동 생성되었다면 과거 마이그레이션을 무조건 재실행하지 않는다.
   적용 이력을 확인한 다음 `0006_gcal_bid_workflow.sql`만 운영 DB에 적용한다.
4. 빌드 및 검증 후 기존 webapp 프로젝트에 배포한다. 0006 테이블을 먼저 생성해야 새 목록 API가 동작한다.
5. /gcal에서 기존 메모, 목록 전체 건수, 회사별 저장과 재조회, 충돌 처리, 취소 제외를 확인한다.

이번 변경은 GitHub에서 검토 가능한 코드로 준비한 단계이며 운영 배포/원격 DB 변경은 하지 않는다.
다중 캘린더 통합, 백그라운드 자동 동기화, 외부 마감 알림은 후속 작업이다.
서비스 계정의 캘린더별 접근권한과 실제 운영 배포 설정을 먼저 확인해야 한다.
기존 계산기의 산식은 변경하지 않는다. 하한율이 비어 있으면 제목의 표시율을 먼저 사용한다.
